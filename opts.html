The runtime registry

A runtime is one backend. It is an engine such as llama.cpp, or a hosted API, together with the Chat subclass that talks to it. urai contains no runtimes. A backend package such as rishi calls register_runtime with a Runtime for each one. The cls field is a dotted path string, or the class itself for a backend that you define in your own code. A dotted path is not imported until a chat for that runtime is built.

Runtime field Meaning
name The name of the runtime
cls The Chat subclass that implements the runtime
pats Substrings that mark a model name as belonging to the runtime, such as .gguf for llama.cpp
optional True for a backend that needs a pip extra
extra The pip extra that installs the backend. The default is name
local True when the runtime runs on this machine
caps A function caps(model, model_path) that returns the Caps of a model, or its dotted path
ctx A fixed context window, for a runtime whose models all have the same window

The install property of a Runtime is the pip command that installs the backend. A caller can show it when the backend is missing. register_runtime(rt, dflt=True) also makes rt the runtime that a bare Chat() uses.

Runtimes are tried in the order of registration. Ollama names a Hugging Face GGUF repository as hf.co/...-GGUF. This name also contains gguf. Register Ollama before llama.cpp. Otherwise llama.cpp takes every such name for a local file. The example registers three placeholder runtimes, so the rest of this page runs without a real backend.

Naming a model

Three rules say which runtime a model needs. They apply in this order.

Rule Example
An explicit runtime= argument runtime='llama'
A runtime name as a prefix of the model name llama/qwen3-4b
A match between the model name and the pats of a runtime qwen3-4b.gguf

split_runtime removes a prefix only when the prefix names a registered runtime. The name openai/gpt-5.1 keeps its vendor prefix. infer_runtime returns the first registered runtime whose pats match the name. It returns None when none match.

resolve_runtime(model, runtime, model_path) applies the three rules and returns (runtime, model). When the model name gives no match, it tries model_path against the pats. When neither model nor model_path is given, it returns the default runtime. When it cannot decide, it raises ValueError. The message lists all three ways to name the runtime.

Split 'runtime/model' into (runtime, model) when the prefix names a registered runtime.

test_eq(split_runtime('llama/qwen3-4b'), ('llama', 'qwen3-4b'))
test_eq(split_runtime('openai/gpt-5.1'), (None, 'openai/gpt-5.1'))   # 'openai' is not a runtime
test_eq(split_runtime('plain'), (None, 'plain'))
test_eq(infer_runtime('qwen3-4b.gguf'), 'llama')
test_eq(infer_runtime('hf.co/unsloth/qwen3-GGUF'), 'ollama')  # registered first, so it wins
test_eq(infer_runtime('gpt-5.1'), 'remote')
test_eq(infer_runtime('mystery-model'), None)
test_eq(resolve_runtime('gpt-5.1'), ('remote', 'gpt-5.1'))
test_eq(resolve_runtime('llama/anything'), ('llama', 'anything'))
test_eq(resolve_runtime('anything', runtime='llama'), ('llama', 'anything'))
test_eq(resolve_runtime(), ('remote', None))                   # nothing named: the default
test_eq(resolve_runtime(None, model_path='/m/x.gguf'), ('llama', None))
test_fail(lambda: resolve_runtime('mystery'), contains="Can't tell which backend")
test_fail(lambda: resolve_runtime('x', runtime='nope'), contains='Unknown runtime')

A resolved model

resolve(name, runtime, model_path, ctx, **opts) works out what is known about a model without loading it. It returns a ModelSpec.

ModelSpec field Meaning
name The name that the caller typed. It falls back to the model id, then the runtime name
runtime The name of the runtime
model_id The id that the backend receives
ctx The context window in tokens
note Text about how the model was resolved. It is empty when the window is known
opts The keyword options that were passed to resolve

The local property of a ModelSpec is True when the runtime runs on this machine.

The ctx argument decides the window first. When you do not pass it, resolve takes the window from the first rule in this table that applies.

Rule ctx note
The runtime sets ctx The ctx of the runtime ''
The runtime is local DFLT_CTX (128,000) ''
The runtime is hosted The first value of the pair that hosted_ctx returns The second value of that pair. It says when the window is assumed

A ModelSpec is frozen. You can cache it, compare it and pass it between parts of a program. Pass it to mk_chat or Chat. The opts field does not take part in comparisons. Two specs for the same model compare equal when only their opts differ.

ModelSpec

def ModelSpec(

A resolved model: its runtime, the id the backend is given, and its context window.

s = resolve('gpt-5.1')
test_eq((s.name, s.runtime, s.model_id, s.local), ('gpt-5.1', 'remote', 'gpt-5.1', False))
assert s.ctx > 100_000 and s.note == ''
test_eq(str(s), 'gpt-5.1 (gpt-5.1)')
s = resolve('llama/qwen3-4b', ctx=8192, n_gpu_layers=99)
test_eq((s.runtime, s.model_id, s.ctx, s.opts), ('llama', 'qwen3-4b', 8192, {'n_gpu_layers': 99}))
test_eq(s.local, True)
test_eq(resolve('unknown-hosted', runtime='remote').note,
        'context window unknown, assuming 128k')
# `opts` is out of the comparison: the same model twice is the same model
test_eq(resolve('gpt-5.1', temp=0.1), resolve('gpt-5.1', temp=0.9))
test_eq(resolve('gpt-5.1') == resolve('gpt-4o'), False)

Capabilities

model_caps(model, runtime, model_path) returns the Caps of a model without loading the model. It resolves the runtime and calls the caps function of that runtime when one is registered. The table shows the other cases.

Case Result
The runtime cannot be resolved, or is not registered hosted_caps(model)
A hosted runtime with no caps function hosted_caps(model)
A local runtime with no caps function An unknown Caps()
The caps function raises an error or returns nothing An unknown Caps()

model_caps never raises, so a failed check does not stop a chat from starting. load_ref imports an object from a dotted path such as 'pkg.mod.name'. It returns a value that is not a string unchanged.

Options

ChatOpts holds every setting that a chat can take. Each setting has one portable name that all runtimes share. The fields fall into four groups.

Group Fields
Conversation sp (system prompt), tools, messages (history to start from)
Tool loop approve, max_steps, tool_max_len, parallel_tools, max_parallel_tools, final_prompt, cbs, default_cbs
Generation ctx, max_output_tokens, temp, top_k, top_p, seed, think, effort, tool_mode
Credentials api_key, api_key_env, base_url

approve is a function that takes a tool call and returns True when the call may run. The default None runs every call. max_steps is the number of tool calls that one turn can use. final_prompt is sent to the model when that budget runs out. api_key_env names an environment variable that holds the key. A saved configuration can then omit the key. The extra field holds options that no portable field covers.

Field Meaning
think False asks a reasoning model not to deliberate. The default None leaves the option unset.
effort How much a reasoning model deliberates, such as 'low', 'medium' or 'high', for models that grade it. The default '' leaves the option unset.
tool_mode How tool schemas reach the model. 'native' sends them as part of the request. 'tags' writes them into the prompt.
cbs Callbacks that the chat attaches, after the default callbacks.
default_cbs When True, the chat first attaches the callbacks that its backend lists in _dflt_cbs. The default is True.

ChatOpts.create(opts, **kw) builds a ChatOpts from an existing ChatOpts or a dict, plus keyword overrides. ALIASES translates the older names that backends used.

Older name Portable name
reasoning_effort effort
temperature temp
max_tokens max_output_tokens
ctx_limit, n_ctx ctx
system sp

A keyword with no field of its own goes into extra. A backend receives extra unchanged. Backend-only settings such as n_gpu_layers are passed through extra.

set() returns a dict of the fields whose value differs from the default, without extra. A field that you set to its default value does not appear. set() cannot tell it from a field that you did not set. The key property returns api_key, or the value of the environment variable that api_key_env names. It stores nothing on the object.

Every chat setting under the portable name all runtimes share.

o = ChatOpts.create(sp='Be brief.', temp=0.2)
test_eq((o.sp, o.temp, o.max_steps), ('Be brief.', 0.2, 10))
test_eq(o.set(), {'sp': 'Be brief.', 'temp': 0.2})

test_eq(o.extra, {'n_gpu_layers': 99})
test_eq(ChatOpts.create(o, temp=0.9).temp, 0.9)
test_eq(ChatOpts.create(o, seed=1).extra, {'n_gpu_layers': 99})
import os
os.environ['DEMO_KEY'] = 'sk-secret'
test_eq(ChatOpts.create(api_key_env='DEMO_KEY').key, 'sk-secret')
test_eq(ChatOpts.create(api_key='explicit', api_key_env='DEMO_KEY').key, 'explicit')
test_eq(ChatOpts.create(api_key_env='NOT_SET_ANYWHERE').key, None)
test_eq(ChatOpts().key, None)
del os.environ['DEMO_KEY']
test_eq(ChatOpts.create(reasoning_effort='high').effort, 'high')
test_eq(ChatOpts.create(temperature=0.2).temp, 0.2)
test_eq(ChatOpts.create(max_tokens=512).max_output_tokens, 512)
test_eq(ChatOpts.create(ctx_limit=8192).ctx, 8192)
test_eq(ChatOpts.create(n_ctx=8192).ctx, 8192)
test_eq(ChatOpts.create(system='Be brief.').sp, 'Be brief.')
test_eq(ChatOpts.create(reasoning_effort='high').extra, {})   # aliased, not shunted into extra
test_eq(ChatOpts.create({'sp': 'from a dict'}).sp, 'from a dict')
o = ChatOpts.create({'temperature': 0.5, 'custom': 1, 'extra': {'a': 2}}, extra={'b': 3}, temp=0.7)
test_eq((o.temp, o.extra), (0.7, {'a': 2, 'b': 3, 'custom': 1}))   # dicts take aliases and extras like keywords
test_eq(ChatOpts.create({'temp': .2, 'temperature': .3}, temp=.9).temp, .9)   # keywords win even through an alias
test_eq(ChatOpts.create(), ChatOpts())
test_eq(ChatOpts().set(), {})

Translating for a backend

A backend translates the portable names with two class attributes on its Chat subclass.

Attribute Meaning
_opt_map A dict from a portable name to the name that the backend uses
_opt_skip The options that the backend cannot use

Chat.map_opts, on the chat page, applies both. It drops a skipped option without a warning. It renames every other option and passes it on. A target name with a dot in it is nested. The entry {'ctx': 'eng_kw.max_num_tokens'} sends the window as eng_kw={'max_num_tokens': ...}. set_dotted builds the nested dict.

test_eq(set_dotted({}, 'plain', 1), {'plain': 1})

One turn at a time

Some settings can change between two calls without a new chat. Examples are a higher effort for a hard question and temp=0 for an extraction. GEN_OPTS lists these settings: max_output_tokens, temp, top_k, top_p, seed, think, effort and tool_mode.

turn_kw(opts, **kw) builds a ChatOpts from opts and kw. It returns the fields of GEN_OPTS that differ from their defaults, and all extra options. It leaves out the other fields, such as the system prompt sp, which apply to the whole chat.

source

turn_kw

The settings in opts and kw that can apply to a single turn, plus any extra options.

test_eq(turn_kw(temp=0.9, effort='high'), {'temp': 0.9, 'effort': 'high'})
test_eq(turn_kw(temp=0.9, sp='ignored here'), {'temp': 0.9})
test_eq(turn_kw(), {})
test_eq(turn_kw(ChatOpts(temp=0.1), temp=0.9), {'temp': 0.9})
