sandbox

Running Python fences produced by a model.

Fences

extract_code(text) returns the code in the last ```python or ```py fence of a reply. It returns None when the reply has no such fence. A model that corrects itself leaves both versions in the reply, and the last version is the one it means.

mk_result_fence(out) puts the output out in a ```result fence. It adds a request to the model. If the output answers the request, the model gives the final answer in prose. If not, the model writes another Python fence.

Running it

chat.run_py(code) runs code in a sandbox namespace that belongs to the chat. The namespace lasts as long as the chat. A model can define a function in one fence and call it in the next.

Case Result of run_py
The code prints text and its last line is an expression The printed text, then the repr of the value
The code prints text only, or has a value only That one part
The code prints nothing and has no value (ok)
The code raises an exception The exception as a string, for example ZeroDivisionError: division by zero

run_py returns the exception as a string, in the same way that a failing tool returns its error. The model reads the string and can fix the code.

ban_defs and g go to the RunPython class of safepyrun. They have an effect only on the first call of run_py for a chat, when run_py creates the namespace.

run_coro(coro) runs an awaitable to completion from synchronous code. It uses fastcore’s shared background event loop.

class _FenceChat(Chat):
    "A chat whose replies are scripted, for testing the fence loop without a model."
    _runtime, ctx_limit, token_count = 'fence', 8192, 0
    def __init__(self, model=None, *, script=(), **kw):
        self.script, self.steps = list(script), 0
        self._setup(model, ChatOpts.create(kw.pop('opts', None), **kw))
    def _send(self, msg, **kw):
        self.turn_msg = self.mk_msg(msg)
        if self.turn_msg: self.hist.append(self.turn_msg)
        text = self.script[min(self.steps, len(self.script) - 1)] if self.script else ''
        self.steps += 1
        self.turn_res = Resp({'role': 'assistant', 'content': text})
        self.hist.append(dict(self.turn_res))
        from urai.core import run_cbs
        for _ in run_cbs(self, 'after_response'): pass
        return self.turn_res

register_runtime(Runtime('fence', _FenceChat, ('fence-',)))
c = _FenceChat()
test_eq(c.run_py('1 + 1'), '2')
test_eq(c.run_py('print("hi")'), 'hi\n')
test_eq(c.run_py('x = 5'), '(ok)')          # a statement produces nothing to show
test_eq(c.run_py('x * 2'), '10')            # ...but the namespace persisted
test_eq(c.run_py('1/0'), 'ZeroDivisionError: division by zero')
test_eq(c.run_py('import math\nmath.sqrt(16)'), '4.0')
# a function defined in one round can be called in the next
test_eq(c.run_py('def double(n): return n * 2'), '(ok)')
test_eq(c.run_py('double(21)'), '42')
test_eq(run_coro(asyncio.sleep(0, 'done')), 'done')

The loop

Attach a PyFenceCallback to a chat with cbs=. After each reply, the callback does the following:

  1. It takes the last Python fence of the reply. If there is none, it does nothing.
  2. It calls the chat’s approve function with a tool call named python, as for any tool call. A refused fence gets the output Denied by human.
  3. It runs the code and stores the output in chat.turn_code_out.
  4. It sends the output to the model with mk_result_fence. This starts another round.

In a streamed turn, the callback also yields the result fence and the next reply into the stream.

Pass pyrun to use your own runner instead of chat.run_py.

Parameter Default Effect
max_rounds 5 The most rounds of code in one turn. It stops a model that never stops writing code.
done None A function that takes the chat and returns True when the task is finished. With None, the loop stops when a reply has no Python fence.
pyrun None A function that runs the code instead of chat.run_py.

When done returns True, the loop records the output in the history as the final message. It makes no further model call.

Two done functions are ready to use:

  • output_matches(expected) returns a done function. That function returns True when the last code output contains expected.
  • task_complete is itself a done function. It calls classify outside the conversation, with the labels complete and needs_more_work. It returns True when the model answers complete.
Setting of task_complete Value
Messages shown to the model The last 6 of chat.hist

The value 6 is fixed in the code. There is no constant or parameter for it.

If a chat has more than one PyFenceCallback, only the one attached last runs. A warning says this once. A callback that you pass for one call can override a callback attached to the chat.

c = _FenceChat(script=['```python\nwhatever\n```', 'ok'],
               cbs=[PyFenceCallback(pyrun=lambda code: seen.append(code) or 'from my runner')])
c('go')
test_eq((seen, c.turn_code_out), (['whatever'], 'from my runner'))
# two registered callbacks: the last one drives, and says so once
c = _FenceChat(script=['```python\n1\n```', 'ok'])
first_cb, last_cb = PyFenceCallback(), PyFenceCallback(done=output_matches(1))
c.add_cbs([first_cb, last_cb])

    warnings.simplefilter('always')
    c('go')
test_eq(len(caught), 1)
assert 'last-registered' in str(caught[0].message)

Driving async code from sync code

Some client libraries offer only async streaming, and Chat is synchronous. sync_iter(agen_fn, stop) lets synchronous code loop over an async generator.

sync_iter calls agen_fn() to create the generator. It gets each item by running the next step of the generator on fastcore’s shared background event loop. Every step runs on the same loop. asyncio.run would start a new loop for each item, and that breaks a streaming connection that belongs to the first loop. An exception from the source generator passes to the caller unchanged.

stop is an optional threading.Event. When another thread sets it, for example from a stop button, the stream ends. sync_iter checks stop before each item, then closes the source generator. The source generator also closes when you close the returned generator or leave the loop early.

killed_on_exit(proc) is a context manager for a subprocess proc.

How the block ends What killed_on_exit does
Normally It waits for the process to exit.
With an exception or an interrupt It terminates the process. If the process is still running after timeout seconds (default 2), it kills the process. It then closes the pipes of the process and raises the exception again.

async def _count(n=3):
    for i in range(n):
        await asyncio.sleep(0)
        yield i

test_eq(list(sync_iter(_count)), [0, 1, 2])
async def _boom():
    yield 1
    raise ValueError('from the source')

it = sync_iter(_boom)
test_eq(next(it), 1)
test_fail(lambda: next(it), contains='from the source')   # the source's error, not a wrapper's
# `stop` ends the source, not just the consumer
closed = []
async def _forever():
    try:
        i = 0
        while True:
            await asyncio.sleep(0.01); yield i; i += 1
    finally: closed.append(True)

stop = threading.Event()
out = []
for o in sync_iter(_forever, stop):
    out.append(o)
    if len(out) == 3: stop.set()
test_eq(out[:3], [0, 1, 2])
test_eq(closed, [True])      # the source generator was closed, not left running
assert len(out) <= 5         # a chunk or two may already be in flight, but no more
p = subprocess.Popen(['sleep', '30'])
try:
    with killed_on_exit(p): raise KeyboardInterrupt
except KeyboardInterrupt: pass
test_eq(p.poll() is not None, True)          # killed, not waited for
p = subprocess.Popen(['true'])
with killed_on_exit(p): pass
test_eq(p.returncode, 0)                     # a normal exit still waits
