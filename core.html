System certificates

Some company networks send HTTPS traffic through a proxy. The proxy signs the traffic again with the company’s own certificate. Python HTTP clients trust only the certificates bundled in certifi. Behind such a proxy, every hosted backend fails with a TLS handshake error. The error does not mention the proxy.

use_system_certs makes Python’s ssl module trust the certificate store of the operating system. The company certificate is in that store. The function imports truststore. It returns False when that import fails. Urai calls the function once on import. Set URAI_SYSTEM_CERTS=0 to turn this off. The older name RISHI_SYSTEM_CERTS is also read. Pass force=True to apply the change regardless of that setting.

source

    force:bool=False

test_eq(use_system_certs(force=True), True)
del os.environ['URAI_SYSTEM_CERTS']

Usage

UsageStats records the tokens that one chat turn used. A local backend reports only prompt tokens and completion tokens. Prompt tokens are the tokens sent to the model. Completion tokens are the tokens the model generated. A hosted provider can also report tokens read from its prompt cache, tokens written to it, reasoning tokens, and the cost in dollars. A field that the backend does not report stays at zero.

Two UsageStats values add field by field. The usage of a whole session is the sum of its turns. Adding None returns the other value unchanged. The sum keeps the model of the first value that names one. The cell below adds two turns:

source

UsageStats

def UsageStats(
    prompt_tokens:int=0, # tokens in the prompt
    completion_tokens:int=0, # tokens the model generated
    total_tokens:int=0, # prompt + completion, as the backend reports it
    n:int=0, # turns folded into this total
    cached_tokens:int=0, # prompt tokens served from a KV or prefix cache
    cost:float=0.0, # what the provider charged; 0 for local inference
    model:NoneType=None, # which model spent them
    reasoning_tokens:int=0, # thinking tokens, which hosted providers bill separately
    cache_creation_tokens:int=0, # tokens written to the provider's prompt cache
):

Token usage for one chat turn.

a = UsageStats(prompt_tokens=10, completion_tokens=5, total_tokens=15, n=1, model='gpt-5.1')
b = UsageStats(prompt_tokens=3, completion_tokens=2, total_tokens=5, n=1)
tot = a + b
tot
total=20|in=13|out=7|turns=2|model=gpt-5.1
test_eq((tot.prompt_tokens, tot.completion_tokens, tot.total_tokens, tot.n), (13, 7, 20, 2))
test_eq(tot.model, 'gpt-5.1')
test_eq(sum([a, b]).total_tokens, 20)   # `sum` starts at 0, which `__radd__` absorbs
test_eq(a + None, a)
test_eq(repr(b), 'total=5|in=3|out=2|turns=1')
test_eq(repr(UsageStats(total_tokens=9, cost=0.25, cached_tokens=4)),
        'total=9|in=0|out=0|turns=0|cached=4|cost=$0.2500')
test_eq(UsageStats().fmt(), '')

Callbacks

A callback is an object with methods that run at fixed points in a chat turn. The method before_send runs just before the message is sent. The method after_response runs just after the reply arrives. Urai uses callbacks to add behavior to a turn without a change to the backend. Counting tokens, recording history, and reminding the model about its tools are all callbacks.

To write a callback, subclass ChatCallback and define a method named after the event. The callback reads any attribute it does not define from the chat it is attached to. In the method, self.turn_res is the current reply of the chat. The attribute order sets which callback runs first. The callback with the lowest order runs first. Setting run=False turns a callback off and keeps it attached.

run_cbs(chat, event) runs one event on every callback of a chat. A callback method can yield values. run_cbs passes them to its caller. A callback uses this to add text to a streamed reply. In the example below, Quiet has the lower order and runs first:

source

ChatCallback

def ChatCallback(
    *args, **kwargs
):

Base class for chat callbacks. A callback reads attributes it lacks from the chat, for example self.turn_msg.

class TinyChat: pass
class Loud(ChatCallback):
    order = 1
    def after_response(self): yield f'loud saw {self.turn_res}'
class Quiet(ChatCallback):
    order = 0
    def after_response(self): yield 'quiet first'
c = TinyChat(); c.turn_res = 'hi'; c.cbs = L(Loud(), Quiet())
for cb in c.cbs: cb.chat = c
test_eq(list(run_cbs(c, 'after_response')), ['quiet first', 'loud saw hi'])
test_eq(list(run_cbs(c, 'before_send')), [])   # no callback defines it
c.cbs[0].run = False
test_eq(list(run_cbs(c, 'after_response')), ['quiet first'])
test_eq(repr(Quiet()), 'Quiet')

Reading a reply

A reply is a plain dict in the OpenAI chat format. Its content is a string or a list of typed parts. A typed part is a dict such as {'type': 'text', 'text': ...}. A tool call is a request from the model to run one of your functions. A tool call is also a typed part. Backends produce both forms of content. Do not index into content to get the words of a reply.

resp_text returns the text of a reply in either form. It joins the text parts and skips the other parts. It returns an empty string for anything that is not a dict. thought returns what a reasoning model wrote before it answered. Urai keeps this text under channels['thought']. truncated returns True when the reply was cut off at the output token limit. has_tool_call returns True when a streamed chunk holds a tool call.

Rendering

Resp is a dict subclass that displays itself as markdown in a notebook. The display has four parts, in this order. The first part is the thinking of the model, as a quoted block. The second part is the answer text. The third part is one line for each tool call. The fourth part is one line for each tool result. Backends return Resp objects. A reply shows formatted when you evaluate it in a notebook cell.

Three helpers format the parts. quote_ makes a thinking block, and Resp uses it. tc_summary_ makes a one-line summary of a tool call, and the stream formatter below uses it. mk_tr_details makes a collapsible block that holds the arguments and the result of a tool call as JSON. No other code in the urai package calls mk_tr_details.

Streaming

A streamed reply arrives as many small chunk dicts. Each chunk holds a few tokens of thinking or answer text. StreamFormatter turns the chunks into markdown that you can print or display as it arrives. It opens a quoted thinking block at the first thinking chunk and adds to the block as more thinking arrives. It closes the block when the answer text starts or the stream ends. showthink=False hides thinking. showcalls=True adds a line for each tool call.

display_stream takes the markdown chunks that a streaming chat produces. It shows them in one notebook output that updates in place. It returns the full markdown.

source

StreamFormatter

def StreamFormatter(
    mx:int=2000, showthink:bool=True, showcalls:bool=False
):

Format a chunk stream to markdown. Thinking streams as one blockquote.

chunks = [{'channels': {'thought': 'let me'}}, {'channels': {'thought': ' see'}},
          {'content': 'the answer'}]
test_eq(''.join(StreamFormatter().format_stream(chunks)),
        '> **🧠 Thinking**\n>\n> let me see\n\nthe answer')
f = StreamFormatter()
test_eq(''.join(f.format_stream([{'channels': {'thought': 'just thinking'}}])),
        '> **🧠 Thinking**\n>\n> just thinking\n\n')   # closed at the end of the stream
test_eq(f.outp, '> **🧠 Thinking**\n>\n> just thinking')  # ...but the close is not part of the text
test_eq(''.join(StreamFormatter(showthink=False).format_stream(chunks)), 'the answer')
call = [{'content': [{'type': 'tool_call', 'name': 'add', 'arguments': {'a': 1}}]}]
test_eq(''.join(StreamFormatter(showcalls=True).format_stream(call)),
        '\n- ⏳ <code>add(a=1)</code>\n')
test_eq(''.join(StreamFormatter().format_stream(call)), '')   # calls are hidden by default

Stock callbacks

This page defines two stock pieces that need nothing from the tool loop. The callbacks that need the tool loop are in loop.

tool_reminder_ is the text that ToolReminderCallback adds to a message when the chat has tools. The text asks the model to summarize each tool result in prose before it continues. TruncationCallback(max_tokens) marks the reply as truncated when the completion tokens of the turn reach max_tokens. Use it with a backend that reports usage but does not report when it stops at the limit.

source

TruncationCallback

def TruncationCallback(
    max_tokens
):

Flag a reply that reaches the output cap when usage data is available.

c = TinyChat(); c.use = UsageStats(completion_tokens=100); c.turn_res = Resp({'content': 'cut off'})
c.cbs = L(TruncationCallback(max_tokens=100)); c.cbs[0].chat = c
list(run_cbs(c, 'after_response'))
test_eq(truncated(c.turn_res), True)
c.use = UsageStats(completion_tokens=99); c.turn_res = Resp({'content': 'room to spare'})
list(run_cbs(c, 'after_response'))
test_eq(truncated(c.turn_res), False)
