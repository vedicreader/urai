record

Recording model turns for deterministic replay.

What is worth remembering

Some failures depend on the request. A backend that rejects an unknown tool rejects it every time. RecordCache records these failures and replays them like replies. Other failures are temporary: a rate limit, a timeout, a connection reset, or a 502, 503 or 504 from the server. A recording of a temporary failure would replay it for ever. is_transient(e) finds these failures from the type or the message of the exception. RecordCache raises them and does not save them. NotRecordable marks a reply that cannot be stored. is_transient treats it as temporary. RecordCache does not save it.

The cache

RecordCache records and replays the result of any function call. CachedChat uses it, and you can use it directly. Call it with a key and a function. If the key has a recording, RecordCache returns the saved value. If the saved result is an error, it raises RuntimeError with the saved error type and message. If the key has no recording, it runs the function and saves the result. It also saves an exception, unless is_transient is true for it.

key(*parts) hashes its arguments together with KEY_VERSION and returns a stable key. A higher KEY_VERSION makes every existing recording miss. forget(key) deletes one recording and returns True if there was one.

record controls what happens on a miss. If record is False, a miss raises KeyError. The message names the environment variable to set. If record is None, RecordCache reads the environment variable named by env (default URAI_RECORD_CHAT). The value 1 turns recording on. The value 0, or no value, turns it off. path is the directory of the recordings (default chatcache).

def RecordCache(

Record what a call returned the first time and replay it on later calls with the same key.

d = tempfile.mkdtemp()
rec = RecordCache(d, record=True)
calls = []
test_eq(rec(rec.key('a'), lambda: calls.append(1) or 'first'), 'first')
test_eq(rec(rec.key('a'), lambda: calls.append(1) or 'second'), 'first')
test_eq(len(calls), 1)
test_eq(rec.run(rec.key('a'), lambda: 'second'), ('first', True))   # `run` also says it was a replay
test_eq(rec.key('a') == rec.key('a'), True)
test_eq(rec.key('a') == rec.key('b'), False)
test_eq(RecordCache(d, record=True, version=99).key('a') == rec.key('a'), False)
# a failure caused by the request is recorded and replays
test_fail(lambda: rec(rec.key('bad'), lambda: (_ for _ in ()).throw(ValueError('no such tool'))))
test_fail(lambda: rec(rec.key('bad'), lambda: 'never runs'), contains='ValueError: no such tool')
test_fail(lambda: rec(rec.key('flaky'), lambda: (_ for _ in ()).throw(TimeoutError('429'))))
test_eq(rec.key('flaky') in rec.cache, False)        # forgotten, so the next run may try again
# with recording off, a miss is an error that says how to fix itself
ro = RecordCache(d, record=False)
test_fail(lambda: ro(ro.key('unseen'), lambda: 'x'), contains='URAI_RECORD_CHAT=1')
test_eq(ro(rec.key('a'), lambda: 'x'), 'first')      # ...but a hit still replays
test_eq(rec.forget(rec.key('a')), True)
test_eq(rec.forget(rec.key('a')), False)             # already gone
os.environ['URAI_RECORD_CHAT'] = '0'
test_eq(RecordCache(d).record, False)                # '0' means no, not "a non-empty string"
os.environ['URAI_RECORD_CHAT'] = '1'
test_eq(RecordCache(d).record, True)
del os.environ['URAI_RECORD_CHAT']
test_eq(RecordCache(d).record, False)

The chat

A recording must be found again only when the same reply would be expected, so the key of each turn includes everything the reply depends on: the model, the arguments it was built with, the system prompt, the names of the tools, and the conversation so far. canon_msg(m) reduces one history message to the parts that go into the key: its role, its text, a short hash of each image or audio part, and its tool calls. Hashing media keeps keys small.

source

as_resp

def as_resp(
    r
):

Convert reply r, a mapping or plain text, to a dict that can be recorded, else raise NotRecordable.

as_resp(r) converts a reply to a dict that RecordCache can save. A mapping becomes a dict. Plain text becomes an assistant message. Any other type raises NotRecordable. A streamed turn is one such type: it arrives as a generator, and its repr would store a memory address as the answer. NotRecordable is transient. RecordCache never saves such a reply.

as_resp('just text'), as_resp({'role': 'assistant', 'content': 'a mapping'})
test_eq(as_resp('just text'), {'role': 'assistant', 'content': 'just text'})
test_eq(as_resp({'role': 'assistant', 'content': 'a mapping'}),
        {'role': 'assistant', 'content': 'a mapping'})
test_eq(as_resp(Resp({'role': 'assistant', 'content': 'a Resp'}))['content'], 'a Resp')
test_eq(resp_text(Resp(as_resp('just text'))), 'just text')

# a streamed turn arrives as a generator, and its `repr` is a memory address rather than an answer
def _gen(): yield 'chunk'
test_fail(lambda: as_resp(_gen()), contains='cannot record a generator')
test_fail(lambda: as_resp(42), contains='cannot record a int')
test_eq(is_transient(NotRecordable('x')), True)            # so it is never cached
test_eq(canon_msg({'role': 'user', 'content': 'hi'}), ['user', 'hi', [], []])
from urai.msgs import ToolCall, mk_msg
test_eq(canon_msg({'role': 'assistant', 'content': '', 'tool_calls': [ToolCall('add', {'a': 1})]}),
        ['assistant', '', [], [('add', {'a': 1})]])
png = b'\x89PNG\r\n\x1a\n' + b'\x00' * 40
m = canon_msg(mk_msg(['look', png]))
test_eq((m[0], m[1]), ('user', 'look'))
test_eq(len(m[2][0]), 16)              # the picture is hashed, not carried into the key

CachedChat(model, path, record, sp, tools, env, **kw) takes model, sp and tools as Chat does. path, record and env configure the RecordCache. CachedChat passes the other keywords to Chat when it builds a real chat. It builds the real chat only when a request has no recording. A run of only replays never loads a model and never opens a connection.

A recording holds every message that the turn added to the history, and not only the final answer. For a tool turn these messages are the call, the result and the answer. The history after a replay is the same as the history after the live turn. The key of the next turn is the same too.

CachedChat also records oneshot, classify and structured. Their keys do not include the conversation, because these methods do not use it. reconfigure changes the system prompt or the tools for later turns. Both are part of the key. CachedChat does not keep a cancelled turn, because a replay would repeat the cut-off reply. The examples use _CountChat, a backend that counts how many times a real chat was built. The count shows which calls were replays.

CachedChat

def CachedChat(
    model:NoneType=None, # anything `Chat` takes; part of the key
    path:NoneType=None, # the diskcache directory; None uses `CHAT_CACHE`
    record:NoneType=None, # ask a real model on a miss; None reads `$URAI_RECORD_CHAT`
    sp:str='', # system prompt, part of the key
    tools:NoneType=None, # tools for the real chat; their names are part of the key
    env:str='URAI_RECORD_CHAT', # the environment variable that turns recording on
    **kw
):

A Chat stand-in that records replies to disk and replays them without loading a model.

built = []

class _CountChat(Chat):
    "Counts how often a real chat was built and asked, so replays can be told from live calls."
    _runtime, ctx_limit, token_count = 'count', 8192, 0
    def __init__(self, model=None, **kw):
        built.append(model)
        self._setup(model, ChatOpts.create(kw.pop('opts', None), **kw))
    def _send(self, msg, **kw):
        self.hist.append(self.mk_msg(msg))
        self.turn_res = Resp({'role': 'assistant', 'content': f'reply to {msg}'})
        self.hist.append(dict(self.turn_res))
        return self.turn_res
    def _oneshot(self, prompt, sp='', think=None, max_tokens=None): return f'oneshot: {prompt}'

register_runtime(Runtime('count', _CountChat, ('count-',)))
d = tempfile.mkdtemp()
c = CachedChat('count-1', path=d, record=True, runtime='count')
test_eq(resp_text(c('hello')), 'reply to hello')
test_eq(built, ['count-1'])                # built once, on the first miss
built.clear()
c2 = CachedChat('count-1', path=d, record=False, runtime='count')
test_eq(resp_text(c2('hello')), 'reply to hello')
test_eq(built, [])                         # replayed, so no chat was ever built
test_eq([m['role'] for m in c2.hist], ['user', 'assistant'])   # ...and the history came back
# the conversation so far is part of the key, so the same prompt twice is two recordings
test_fail(lambda: c2('hello'), contains='no recording')
test_eq(resp_text(c('hello')), 'reply to hello')   # the recorder can, and records the second turn
test_eq(resp_text(c2('hello')), 'reply to hello')  # ...so now the replayer can too
c3 = CachedChat('count-1', path=d, record=False, sp='a different briefing', runtime='count')
test_fail(lambda: c3('hello'), contains='no recording')   # sp is part of the key
built.clear()
c4 = CachedChat('count-1', path=d, record=True, runtime='count')
test_eq(c4.oneshot('what is 2+2?'), 'oneshot: what is 2+2?')
c4('hello')                                          # a turn that changes the history
test_eq(c4.oneshot('what is 2+2?'), 'oneshot: what is 2+2?')
test_eq(len([b for b in built]), 1)                  # one chat; the second oneshot replayed
test_eq(c4.reconfigure(sp='new').sp, 'new')
test_eq(c4.cancelled, False)
c4.close()
test_eq(c4.cancel(), False)                # nothing live to stop

structured saves the reply as a dict. A replay rebuilds the schema object from the dict, because pickle cannot save a dataclass that is defined at runtime. runtime reads the runtime from the model name and does not build a chat.

from dataclasses import dataclass
@dataclass
class _Two:
    a: str
    b: int

class _StructChat(_CountChat):
    _runtime = 'struct'
    def structured(self, prompt, schema, sp=None): return schema(a=prompt, b=len(prompt))

register_runtime(Runtime('struct', _StructChat, ('struct-',)))

f = tempfile.mkdtemp()
built.clear()
cs = CachedChat('struct-1', path=f, record=True, runtime='struct')
test_eq(cs.structured('hi', _Two), _Two('hi', 2))
test_eq(built, ['struct-1'])

built.clear()
cs2 = CachedChat('struct-1', path=f, record=False, runtime='struct')
test_eq(cs2.structured('hi', _Two), _Two('hi', 2))   # the dict on disk comes back as the schema
test_eq(built, [])                                   # and nothing was built to do it
test_eq(cs2.runtime, 'struct')                       # off the id, with no engine either
assert cs2._chat is None

@dataclass
class _Nest:
    kids: list[_Two]

class _NestChat(_StructChat):
    _runtime = 'nest'
    def structured(self, prompt, schema, sp=None): return schema([_Two(prompt, 1)])

register_runtime(Runtime('nest', _NestChat, ('nest-',)))
n1 = CachedChat('nest-1', path=f, record=True, runtime='nest')
n1.structured('hi', _Nest)
n2 = CachedChat('nest-1', path=f, record=False, runtime='nest')
test_eq(n2.structured('hi', _Nest), _Nest([_Two('hi', 1)]))   # a replay rebuilds the nested objects too

A turn can also remove or rewrite old messages, as a sliding window does. The recording holds the whole history after the turn, so a replay ends with the same hist the live turn did. Recordings made before this kept only the messages a turn appended, and a replay still reads them.

class _WindowChat(_CountChat):
    _runtime = 'window'
    def _send(self, msg, **kw):
        if len(self.hist) > 2: del self.hist[0]     # the oldest message falls out of the window
        return super()._send(msg, **kw)

register_runtime(Runtime('window', _WindowChat, ('window-',)))
w = tempfile.mkdtemp()
lw = CachedChat('window-1', path=w, record=True, runtime='window')
for q in ('a', 'b', 'c'): lw(q)
rw = CachedChat('window-1', path=w, record=False, runtime='window')
for q in ('a', 'b', 'c'): rw(q)
test_eq(rw.hist, lw.hist)
[m['content'] for m in rw.hist]

use adds the usage of every reply, replayed or live, as Chat.use does. A recording saves the real cost of the call. A replayed turn reports that cost. You can test code that depends on usage, such as a budget or a check of how full the context is, from recordings.

class _PaidChat(_CountChat):
    "Answers with a usage block, the way a hosted backend does."
    _runtime = 'paid'
    def _send(self, msg, **kw):
        self.hist.append(self.mk_msg(msg))
        self.turn_res = Resp({'role': 'assistant', 'content': f'reply to {msg}',
                              'usage': {'prompt_tokens': 100, 'completion_tokens': 7,
                                        'total_tokens': 107, 'cost': 0.002, 'model': 'paid-1'}})
        self.hist.append(dict(self.turn_res))
        return self.turn_res

register_runtime(Runtime('paid', _PaidChat, ('paid-',)))
e = tempfile.mkdtemp()
live = CachedChat('paid-1', path=e, record=True, runtime='paid')
live('hello')
live.use
test_eq((live.use.total_tokens, live.use.completion_tokens, live.use.n), (107, 7, 1))
test_eq(live.use.cost, 0.002)
test_eq(live.use.model, 'paid-1')

# and the replay reports the same, without building a chat
built.clear()
replayed = CachedChat('paid-1', path=e, record=False, runtime='paid')
replayed('hello')
test_eq(built, [])                                        # nothing was built, so nothing was asked
test_eq(replayed.use.total_tokens, live.use.total_tokens)
test_eq(replayed.use.cost, live.use.cost)

# occupancy, not billing volume: what the window holds after the turn, live or replayed
test_eq((live.token_count, replayed.token_count), (107, 107))

# a reply with no usage block folds a turn and no tokens, rather than raising
plain = CachedChat('count-1', path=d, record=False, runtime='count')
plain('hello')
test_eq((plain.use.total_tokens, plain.use.n), (0, 1))
test_eq(plain.token_count, 0)

use and token_count measure different things. They differ in a turn with a tool call. use is the cost of the turn: the tool loop adds the usage of every model request in the turn. token_count is the number of tokens that the conversation fills in the context window after the turn. It equals the total of the last request only. A recording saves both numbers. A replay reports both. In the example below, the turn makes two requests.

quantity tokens
first request 110
second request 156
use.total_tokens 266
token_count 156 
def weather(city: str):
    "Look up the weather."
    return f'{city}: fine'

class _StepChat(ToolLoopMixin, Chat):
    "Two model steps, one tool call between them. `ToolLoopMixin._send` does the real totalling."
    _runtime, ctx_limit = 'step', 8192
    def __init__(self, model=None, **kw):
        self._n = 0
        self._setup(model, ChatOpts.create(kw.pop('opts', None), **kw))
    def _model_step(self, **kw):
        self._n += 1
        if self._n == 1: return Resp({
            'role': 'assistant', 'content': '',
            'usage': {'prompt_tokens': 100, 'completion_tokens': 10, 'total_tokens': 110},
            'tool_calls': [{'id': '1', 'type': 'function',
                            'function': {'name': 'weather', 'arguments': {'city': 'Madurai'}}}]})
        return Resp({'role': 'assistant', 'content': 'fine',
                     'usage': {'prompt_tokens': 150, 'completion_tokens': 6, 'total_tokens': 156}})

register_runtime(Runtime('step', _StepChat, ('step-',)))
f = tempfile.mkdtemp()
stepped = CachedChat('step-1', path=f, record=True, runtime='step', tools=[weather])
res = stepped('weather in Madurai?')
res['usage'], stepped.token_count
test_eq(res['usage']['total_tokens'], 266)      # 110 + 156: what the two steps together cost
test_eq(stepped.use.total_tokens, 266)          # ...which is what `use` counts
test_eq(stepped.token_count, 156)               # ...and the window holds the last step, not the sum

# the replay reports both, from the same recording
again = CachedChat('step-1', path=f, record=False, runtime='step', tools=[weather])
again('weather in Madurai?')
test_eq((again.use.total_tokens, again.token_count), (266, 156))
