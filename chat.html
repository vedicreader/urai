When the window fills

A model reads a limited number of tokens at once. This limit is the context window. When a conversation grows past it, each engine fails in its own way. The exception message usually mentions the context, the KV cache or n_ctx.

Three names refer to the window size. ctx is the portable option, in tokens, that urai passes to the backend. n_ctx is the name that llama.cpp uses, and urai accepts it as an alias of ctx. chat.ctx_limit is an attribute that a backend sets to the window size it uses. Chat does not define it. chat.pct_full and the tool loop read ctx_limit, and a value of 0 means that the window size is unknown.

is_ctx_error(chat, e) returns True when exception e from a backend means that the window is full. It checks two things in order. First it looks for a known phrase in the lowercased message. Then it checks whether chat.pct_full is at least 1 while chat.ctx_limit is set. It returns False when that check raises an error. The tool loop uses it to decide when to try recovery. The tool loop raises ContextWindowExceededError when recovery also fails.

The tool loop writes three message strings into the history.

String When the tool loop writes it
budget_msg_ The tool-call budget (max_steps) runs out
cancel_msg_ The user stops a turn before a tool call runs
cancelled_reply_ The user stops a streamed turn before any answer text arrives. It is the answer text of that turn.

The chat

Chat(model) returns an instance of the subclass for the runtime of model. A backend writes this subclass. The table shows what a subclass sets.

Member Meaning
_runtime The name under which the subclass is registered
_opt_map, _opt_skip The option translations described on the opts page
_send A method that sends one message and returns the reply
_stream A method that does the same and yields chunks
_media_ok False for a backend that cannot send images or audio. The default is True
_media_note The message of the TypeError that Chat raises when a message holds media and _media_ok is False. It says what to use instead

media_in is True when pictures that tools return reach the model. Its default is the value of _media_ok. You can set it for a model that behaves differently.

The settings of a chat are in one ChatOpts object, chat.opts. fmt2hist converts messages in the format of the backend into the canonical history. map_opts translates portable option names into the names of the backend.

source

Chat

def Chat(
    model:NoneType=None, *, runtime:NoneType=None, model_path:NoneType=None, opts:NoneType=None, **kw
):

A conversation with any registered backend; Chat(model) returns the subclass for the model’s runtime.

Eight ChatOpts fields are also attributes of the chat: sp, approve, max_steps, tool_max_len, parallel_tools, max_parallel_tools, final_prompt and ctx. Each attribute reads chat.opts. Setting an attribute replaces chat.opts with a copy that has the new value. The chat keeps no second copy of the setting.

Callbacks

add_cb attaches a callback to the chat and returns it. You can pass a callback class, which is instantiated for you, or an instance. add_cbs attaches several. remove_cb takes an instance, or a class to remove every callback of that class, and remove_cbs removes several. A backend’s own default callbacks are attached when the chat is built unless you pass default_cbs=False.

One turn

chat(msg) runs one turn and returns the reply. The stream argument changes the return value.

stream Return value
False (default) The reply
True A generator of markdown strings
'raw' A generator of the chunk dicts that the backend produced

The cbs argument attaches callbacks for this turn only. Keyword options such as temp=0.9 or effort='high' also apply to this turn only. They do not change chat.opts. Only the fields in GEN_OPTS and the extra options pass through, as turn_kw describes.

When the tool-call budget ends a turn, the chat sends final_prompt once. This asks the model to answer with what it has. A Chat keeps state between calls. Do not run two turns on one instance at the same time.

A backend to test against

The examples on this page use _DemoChat, a backend that needs no model. _DemoChat appends one (msg, kw) pair to chat.sent for each request, where msg is the message and kw holds the options of that request. It replies with echo: followed by the message text. It is registered as the demo runtime for names that contain demo-. It is also the default runtime. It maps the option ctx to n_ctx and skips effort.

class _DemoChat(Chat):
    "A backend that answers without a model, so the machinery around one can be tested."
    _runtime, _opt_map, _opt_skip = 'demo', {'ctx': 'n_ctx'}, ('effort',)
    ctx_limit, token_count = 8192, 0

    def __init__(self, model=None, *, runtime=None, model_path=None, opts=None, **kw):
        self.model_id, self.sent = model, []
        self._setup(model, ChatOpts.create(opts, **kw))

    def _send(self, msg, **kw):
        self.sent.append((msg, kw))
        self.turn_msg = self.mk_msg(msg) if msg is not None else None
        if self.turn_msg: self.hist.append(self.turn_msg)
        self.turn_res = Resp({'role': 'assistant',
                              'content': f'echo: {resp_text(self.turn_msg or {})}'})
        self.hist.append(dict(self.turn_res))
        for _ in run_cbs(self, 'after_response'): pass
        return self.turn_res

    def _stream(self, msg, cbs=None, **kw):
        r = self._send(msg, **kw)
        yield resp_text(r)
        return r

register_runtime(Runtime('demo', _DemoChat, ('demo-',)), dflt=True)
c = Chat('demo-1', sp='Be brief.', ctx=4096, temp=0.2)
test_eq(type(c).__name__, '_DemoChat')           # dispatched by the id pattern
test_eq(isinstance(c, Chat), True)
test_eq((c.sp, c.ctx, c.runtime), ('Be brief.', 4096, 'demo'))
test_eq(c.opts.temp, 0.2)
c.sp = 'Be terse.'
test_eq((c.sp, c.opts.sp), ('Be terse.', 'Be terse.'))
test_fail(lambda: Chat('demo-1', max_parallel_tools=-1), contains='at least 1')
test_eq(c.media_in, True)
c.media_in = False; test_eq(c.media_in, False)
c.media_in = None; test_eq(c.media_in, c._media_ok)
r = c('hello')
test_eq(resp_text(r), 'echo: hello')
test_eq([m['role'] for m in c.hist], ['user', 'assistant'])
test_eq(''.join(c('again', stream=True)), 'echo: again')
c('hi', temp=0.9, effort='high')
test_eq(c.sent[-1][1], {'temp': 0.9, 'effort': 'high'})
test_eq(c.opts.temp, 0.2)
test_eq(c.map_opts({'ctx': 8192, 'effort': 'high'}), {'n_ctx': 8192})
class _Counter(ChatCallback):
    def __init__(self): self.n = 0
    def after_response(self): self.n += 1

c = Chat('demo-1')
cb = c.add_cb(_Counter)
test_eq((isinstance(cb, _Counter), cb.chat is c), (True, True))
c('one'); c('two')
test_eq(cb.n, 2)
c.remove_cb(_Counter)
test_eq(len(c.cbs), 0)
c('three')
test_eq(cb.n, 2)
one_off = _Counter()
c('four', cbs=[one_off])
test_eq((one_off.n, len(c.cbs)), (1, 0))
c('five')
test_eq(one_off.n, 1)

Reconfiguring

Some backends hold state that comes from the system prompt and the tools. LiteRT keeps a conversation object. MLX keeps a KV cache. If you assign chat.sp directly, that state is out of date.

reconfigure(sp, tools) changes the system prompt, the tools, or both. It keeps the history. It calls the backend hooks so that the backend rebuilds its state.

Argument value Effect
None (default) The setting stays as it is
tools=() Every tool is removed

A backend implements the hooks _set_sp, _set_tools and _recreate_conv. The versions in Chat do nothing.

source

Change the system prompt or the tools and keep the history; None keeps a value and tools=() removes all tools.

def add(a: int, b: int) -> int:
    "Add two numbers."
    return a + b

c = Chat('demo-1', sp='old')
c('remember this')
c.reconfigure(sp='new', tools=[add])
test_eq((c.sp, c.opts.sp), ('new', 'new'))
test_eq([t.__name__ for t in c.tools], ['add'])
test_eq(len(c.hist), 2)
c.reconfigure(tools=())
test_eq(list(c.tools), [])
c.reconfigure(sp='newer')
test_eq((list(c.tools), c.sp), ([], 'newer'))

Stopping, and the rest

cancel() asks the running turn to stop. You can call it from another thread, such as the stop button of a user interface. The turn checks the cancel flag between streamed chunks and between tool calls. It stops at the next check. Every tool call in the history then has a result, and the next turn can start normally. A backend that cannot interrupt its engine finishes the completion that it is generating before it stops. cancelled is True while the flag is set. The next turn clears the flag.

Method What it does
oneshot(prompt, sp) Asks the model one question outside the conversation, with no tools and no history, and returns the reply text. hist does not change
recover_context(error) Recovers from a full context window. The version in Chat raises ContextWindowExceededError. A backend that can recover overrides it
close() Releases what the backend holds, such as a loaded model
print_hist() Shows the whole conversation as markdown

Async

AsyncChat lets async code use any backend. It wraps a Chat, or builds a Chat from the arguments that you pass. It runs each blocking call in a worker thread, so the event loop keeps running.

Call Result
await achat(msg) The reply
await achat(msg, stream=True) An async iterator of chunks

An async generator cannot return a value. The final reply is the .value of the iterator, after you read every chunk. AsyncChat reads an attribute that it does not define from the wrapped chat. async with calls close() at the end. adisplay_stream is the async version of display_stream.

Approving a tool call

The approve setting of a chat is a function that takes a tool call. It returns True to run the call and False to refuse it. A refused call gets the result Denied by human operator, unless the return value has a reply() method that gives another text. With no approve function, every call runs.

hitl_policy(modes, ask) builds an approve function from a dict that maps tool names to modes. HITL means human in the loop.

Mode of the tool Result
approved The call runs. Nobody is asked
dont_run The call is refused. Nobody is asked
Any other mode, or no entry The function ask decides

The default ask is ask_console. It prints the call and waits for y or N. With http=True, hitl_policy uses http_approval and ignores ask. http_approval posts the call to the path /agent/approval/request at the address in the environment variable URAI_APPROVAL_URL. The default address is http://127.0.0.1:5001. It raises RuntimeError when the request fails. Pass a URL string as http to use another address. The timeout of http_approval is 300 seconds by default.
